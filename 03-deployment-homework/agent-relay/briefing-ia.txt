CONTEXTE DE REPRISE - AGENT RELAY
Date : 2026-09-22

PROJET
Construire puis deployer un relais HTTP permettant a plusieurs agents logiciels de s'enregistrer, s'envoyer des taches, reclamer une tache, l'executer localement et retourner un resultat.

OBJECTIF IMMEDIAT
Conteneuriser le service avec Docker, construire l'image `agent-relay:local`, demarrer le conteneur avec le port 8000 publie, puis verifier les endpoints `/health` et `/ready`.

ARCHITECTURE ACTUELLE
- API FastAPI : `main.py`.
- Persistance SQLite via SQLAlchemy : `database.py`.
- Operations metier et transactions atomiques : `storage.py`.
- Worker externe : `worker.py`.
- Dashboard HTML authentifie : `dashboard.html`, servi par `dashboard.py`.
- Modeles de requetes/reponses : `schemas.py`.
- Tests d'integration : `test_agent_relay.py`.
- Le worker deterministe transforme actuellement `input.upper()`.
- Les agents s'authentifient avec un bearer token.
- Les tokens d'agent et les claim tokens sont stockes uniquement sous forme de hash.
- Cycle de vie : `queued -> processing -> completed`, `processing -> failed`, ou retour a `queued` apres expiration du lease.
- Lease de 60 secondes par defaut, renouvelable par heartbeat.
- Livraison at-least-once, jamais exactly-once.
- Le relay n'execute jamais le texte soumis ; le worker l'execute localement.
- SQLite utilise WAL et `BEGIN IMMEDIATE` pour serialiser les claims concurrents.
- `storage.py` est isole afin de permettre plus tard un port PostgreSQL avec row locking (`FOR UPDATE SKIP LOCKED`).
- Le dashboard necessite de fournir manuellement un token dans le navigateur ; le token est conserve dans `sessionStorage`.

CONTRAINTES ET CHOIX VALIDES
- Pas de broker de messages pour la V1.
- Pas d'execution de code utilisateur dans FastAPI.
- Conserver le protocole HTTP et les regles d'authentification lors du futur portage PostgreSQL.
- Ne jamais exposer les tokens dans le dashboard, les logs ou les listings.
- Les claim tokens sont distincts des tokens d'agent.
- Les requetes terminales identiques sont idempotentes.
- Un resultat utilisant un claim expire doit etre rejete avec `409 stale_claim`.
- Les tests ne doivent pas reinitialiser la base de developpement `agent-relay.db`.
- Le deploiement Docker actuel utilise SQLite dans le conteneur ; la persistance par volume Docker et le portage PostgreSQL sont des sujets ulterieurs, sauf exigence du devoir.
- Ne pas refaire l'architecture fonctionnelle deja implementee : commencer par valider le build et l'execution Docker.
